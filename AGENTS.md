# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository. For current status, decisions and open work, see [`docs/HANDOVER.md`](docs/HANDOVER.md).

## What this is

An MCP (Model Context Protocol) server that exposes the Akilimo agricultural API (IITA) as tools for LLM clients (Claude Desktop, Open WebUI + Ollama, etc.), plus a web UI that acts as a real MCP client for it and for the hosted Akilimo 2.0 server. pnpm monorepo, TypeScript throughout.

## Commands

Run from the repo root (pnpm workspace, Node 20+):

```bash
pnpm install
pnpm dev:server      # MCP server over stdio (vite-node packages/server/src/index.ts)
pnpm dev:server:http # MCP server over HTTP on :3001 (streamable HTTP /mcp, SSE /sse); restarts on changes in server/shared/llm src
pnpm dev:web         # web UI at http://localhost:5173; proxies to the server above
pnpm build           # builds all @akilimo/* packages
pnpm start           # node packages/server/dist/index.cjs
pnpm --filter @akilimo/server build   # build only the server
docker-compose up -d # MCP server (127.0.0.1:3080), demo web UI (127.0.0.1:4173), Open WebUI (127.0.0.1:8089)
```

There is no test suite or linter configured.

Copy `.env.example` to `.env`; `config.ts` loads the repo-root `.env` with `process.loadEnvFile` (existing env vars win). Server env vars: `AKILIMO_API_BASE_URL`, `AKILIMO_API_KEY` (optional), `AKILIMO_DEVICE_TOKEN` (optional), `TRANSPORT` (`http`, or legacy `sse`, for HTTP; stdio otherwise; `--http` flag does the same), `PORT` (default 3001 locally; containers set 3000; port 3000 is taken by Dokploy on the dev machine), `ALLOWED_ORIGINS` (comma-separated CORS list), `DB_*` (accounts PostgreSQL, see below). The web dev proxy reads `AKILIMO_1_MCP_URL` / `AKILIMO_2_MCP_URL`. `docker-compose` additionally requires `WEBUI_SECRET_KEY`.

## Architecture

- **Naming** — this repo's agent is **Akilimo 1.0** (MCP server name and client config key `akilimo-1.0`); the hosted MCP of the Akilimo 2.0 platform is **Akilimo 2.0** (`akilimo-2.0`): streamable HTTP at `https://mcp.akilimo.org/mcp`, partner key required (`Authorization: Bearer` or `X-API-Key`), no CORS support. Use these labels in code and docs.
- **Upstream API** — the Akilimo 1.0 API (Laravel, separate repo `new-akilimo-api`, hosted at `https://api.akilimo.org`, `composer dev` serves it locally on port 8600). Its `routes/api.php`, `app/Rules/*Rules.php` and `app/Data/*Data.php` are the source of truth for endpoints and the compute payload. Where the rules and DTOs disagree (e.g. rules say `unit_price_maize_1`, DTOs read `unit_price_maize1`), follow the DTOs. The R compute service behind it errors with "subscript out of bounds" on values it cannot look up, so shared schema defaults follow what the AKILIMO mobile app sends (`use_case` `FR`, `"NA"` instead of null, yield class instead of 0).
- **`packages/server`** (`@akilimo/server`) — the MCP server, split into modules under `src/`: `index.ts` (entry, picks the transport), `config.ts` (env vars), `server.ts` (builds the low-level `Server` from `@modelcontextprotocol/sdk` and dispatches `ListTools`/`CallTool` to the registry), `tools/` (one file per tool implementing `ToolDefinition` from `tools/types.ts`, registered in `tools/index.ts`), `transports/stdio.ts` and `transports/http.ts`. To add a tool, create a file in `tools/` and add it to the `tools` array; handlers may throw, `server.ts` turns errors into `isError` results. Tools:
  - `get_reference_data` → `GET /v1/{category}` or `/v1/{category}/country/{countryCode}`, all pages merged by `api.getAll` (the API paginates at 50 rows; NG fertilizer-prices has 60). `REFERENCE_CATEGORIES` and `COUNTRY_FILTERABLE` must match the API's public routes; only some categories have a `/country/` route.
  - `get_operation_costs` (`tools/advisory.ts`) → typical land preparation and weeding costs for planting practices advice, ready for `manualCosts`/`tractorCosts`/`weedingCosts`: each is `GET /v1/default-prices` (rows keyed by country, `BU` for Burundi; items `manual_ploughing`, `manual_ridging`, `tractor_ploughing`, `tractor_ridging`, `weeding1`, `weeding2`) when it is believable in US dollars, else the compute service's own default (`BASELINE_COSTS`, copied from `default_lmo_costs` in the `akilimo-recommendations` R repo, `R/AkilimoMain.R`, per acre; it also has harrowing), else the middle band of `GET /v1/operation-costs/country/{code}`, else `null`; each carries `source` and `approx_usd`. The dollar check uses the rough rates in `USD_RATE` (NG 1500, TZ 2600, RW 1450, GH 12, BI 2900 per dollar; refresh them when they drift) and accepts 0.5 to 150 dollars per acre. Tanzanian amounts look huge because the shilling is weak (manual ploughing 175000 is about 67 dollars) and pass; the API's Tanzanian weeding prices (600000 and 450000, about 230 and 170 dollars) fail and the service defaults (60000 and 45000) are used instead. Only Nigeria and Tanzania have data; the compute service ignores harrowing costs in planting practices; Rwanda, Ghana and Burundi need the farmer's own costs.
  - `check_location` (`tools/advisory.ts`) → `GET /v1/coverage/check` of the Akilimo API: is a point inside the area where recommendations can be computed (`covered` true, false, or null when the API has no area for the country or lacks the route; an error from the API becomes `covered: null` so the conversation goes on). The chat instructions tell the model to call it as soon as it has coordinates. The supported area itself is copied from the compute service into the API's `coverage_areas` table (`php artisan coverage:sync`, see that repo's `docs/COVERAGE.md`), and the API also answers 422 to a compute request outside it.
  - `get_crop_prices`, `check_price`, `get_investment_options`, `fertilizer_plan` (`tools/farm-inputs.ts`): `get_crop_prices` gives the second crop of intercropping (NG maize as `fresh_cob`, the API's `cob`, or `grain`; TZ sweet potato `tubers`) with typical price, unit weight (grain's 100 kg is an assumption) and allowed range, ready for `compute_request.maize`/`sweetPotato`; `check_price` tests a price (cassava, maize cob/grain, sweet potato, a fertilizer by key) against the lists' `min_allowed_price`/`max_allowed_price` (0/-1 = no limit; `ok` null when no range is known) and the web UI shows it as a non-blocking warning (`PriceHint`); `get_investment_options` lists the budget choices per area unit and, given the field size, as totals for the field (`max_investment_for_field`; compute's `maxInvestment` is for the WHOLE field, 0/omitted = no limit); `fertilizer_plan` turns `fertilizer_rates` (kg for the whole field) into bags (rounded to half bags like the R service, `planBags` in `@akilimo/shared`) and cost, and the web UI shows the same table under the FR result (`BagPlan`, also in replay).
  - `get_fertilizer_options` / `get_cassava_price` (`tools/advisory.ts`) → compact views (≈3 KB instead of ≈28 KB) with sorted price bands and a middle-band "typical" price, skipping 0/negative placeholder bands. Raw lists overflow small local models, which then guess; prefer these in LLM prompts.
  - `compute_recommendations` → `POST /v1/recommendations/compute` with `{ user_info, compute_request, fertilizer_list }`. The tool's JSON schema is generated from the shared Zod schema (`z.toJSONSchema(..., { io: "input" })`), so defaulted fields are optional for the model. `user_info` is filled with an anonymous `DEFAULT_USER_INFO` that callers may override.
  
  **MCP gateway** (`src/gateway/`, HTTP mode only, mounted at `/gateway`): `registry.ts` keeps the shared MCP server list in the table `mcp_servers` (`DbRegistry`: filled on the first start with an empty table from the old registry file at `GATEWAY_DATA_FILE` if there is one, otherwise with the akilimo-1.0 and akilimo-2.0 defaults; a saved key follows a server whose id changes and is deleted with it) or, without a database, read-only from that file or the defaults (`FileRegistry`); entries are zod-validated (id slug, label, description, http(s) url, auth none/bearer/header, enabled) and the interface is async; seeded with akilimo-1.0 → `http://127.0.0.1:$PORT/mcp` and akilimo-2.0; atomic temp-file writes; zod-validated entries: id slug, label, description, http(s) url, auth none/bearer/header, enabled). `routes.ts` serves the public list (`editable` = requester is an admin), add/edit/remove for signed-in users with the `admin` role (session loaded only on registry routes, JSON-only writes; without a database it is read-only, because registering URLs is an SSRF vector), an admin-only `POST /gateway/test` (`test.ts`: connects with the SDK client using the entry's URL and key setting, lists tools, 20 s timeout, turns fetch/HTML/JSON error bodies into readable messages; nothing saved), and a streaming streamable-HTTP proxy at `/gateway/servers/:id/mcp` that forwards MCP headers and maps the browser's `X-Mcp-Key` to the entry's auth. Keys are never stored server-side.

  **Accounts** (`src/accounts/`, `src/db/`, HTTP mode only, mounted at `/api`): **Drizzle ORM** (`drizzle-orm` + `pg`, plain npm packages with no downloaded engines; it replaced Prisma, whose engine download from `binaries.prisma.sh` failed in Docker builds on a WSL network) with **PostgreSQL only**, configured by Laravel-style `DB_HOST`/`DB_PORT` (5432)/`DB_DATABASE` (`akilimo_mcp`)/`DB_SCHEMA` (`public`)/`DB_USERNAME`/`DB_PASSWORD`; `DB_CLIENT` (or `DB_CONNECTION`) is optional and must be `pgsql`. `db/settings.ts` parses them, treating blank values as unset; it returns `null` when `DB_HOST` is unset (guest-only HTTP mode and stdio mode keep working, `GET /api/auth/status` reports `enabled: false` and everything else is 503) and throws a clear error when a host is set without a username or password. Its `connectionString` (`postgresql://`, credentials URL-encoded) is only for drizzle-kit's database commands; the server itself passes separate fields to `pg`. Schema: `src/db/schema.ts` (table, index and constraint names match what Prisma created, so databases from either tool are the same); migrations: SQL files in `packages/server/drizzle/` (create with `pnpm db:generate`, which needs no database, review the SQL, commit it with `drizzle/meta/`; never edit applied ones; `drizzle.config.ts` configures drizzle-kit). `db/index.ts` `connectDb` opens a `pg` Pool with separate fields (no URL escaping) and runs the migrator (`drizzle-orm/node-postgres/migrator`, folder `./drizzle` relative to the working directory or `DB_MIGRATIONS_DIR`, bookkeeping table `__drizzle_migrations` in `DB_SCHEMA`, default `public`), so every start, `pnpm db:migrate` (`--migrate`) and `--seed-admin` bring the schema up to date and an unreachable or failing database stops start-up with a clear message. `0000_baseline.sql` is hand-edited to be idempotent (`IF NOT EXISTS`, guarded constraints) so databases created by Prisma are adopted; the leftover `_prisma_migrations` table is unused. Queries use the core builder (`db.select().from(...)`), unique violations are PostgreSQL error 23505 (check `error.cause` too), and malformed UUID path ids are answered with 404 before querying. API responses keep snake_case fields. `auth.ts`: scrypt password hashes (`scrypt$N$r$p$salt$hash`), 32-byte session tokens in the HttpOnly SameSite=Lax `akilimo_session` cookie (Secure over HTTPS; `trust proxy` set), only SHA-256 of tokens stored, JSON-only writes as CSRF guard, in-memory rate limit on signup/login. **Usernames**: `users.username` is unique and lowercase (`UsernameSchema` in `auth.ts`: 3-30 of `a-z 0-9 . _ -`, never `@`); signup requires it and returns a 409 that says whether the email or the username is taken; login takes `login` (an email if it contains `@`, otherwise a username; the old `email` field still works); `USER_SELECT` is the user shape in every response. The username column was originally added to existing Prisma-era accounts by a backfill from the email's local part (`usernameFromEmail` follows the same rules). `routes.ts`: signup/login/logout/status, conversations (+ messages, storing the full model history incl. `tool_calls`/`tool_name`; `conversations.mode` is `ai` or `guided`, `GET /api/conversations?mode=` filters, and a guided step is one message with role `tool` whose `messages.data` jsonb holds `{action, country, title, tool, request, result}`, capped at 500 KB) and activity, every query scoped by `user_id`; admin-only `GET /api/admin/users` and `PATCH /api/admin/users/:id` (role change; refuses to demote the last admin). **Roles**: `users.role` is a PostgreSQL enum named `Role` (`user` default, `admin`); `requireAdmin` in `auth.ts` guards admin actions. `seed.ts` ensures an admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD`/`ADMIN_NAME`/`ADMIN_USERNAME` (optional; derived from the email, with a suffix if taken) on every HTTP start and via `--seed-admin` (`pnpm seed:admin`): creates if missing, promotes an existing account, never changes a password or username, and refuses an `ADMIN_USERNAME` that belongs to another account.

  **Chat** (`src/chat/`, HTTP mode only, mounted at `/chat`): the model calls and MCP tool calls of the web chat run on the server, so the browser only sends the conversation. `routes.ts`: `GET /chat/providers` (signed-in users see the providers that are on and set up; admins see every provider with `configured`, `baseUrl`, `keyHint`), `GET /chat/models/:provider` (live list plus the default model), admin-only `POST /chat/test`, `PUT /chat/admin/providers/:id` (`apiKey`, `clearKey`, `baseUrl`, `enabled`), `GET/PUT/DELETE /chat/admin/server-keys/:id`, and `POST /chat`, which validates `{provider, model, country, messages}`, runs the agent loop and streams newline-delimited JSON events (`message`, `step`, `warning`, `error`, `ping`, `done`; a `ping` every 15 s keeps proxies from closing a silent stream, every finished answer ends with `done` and the web client reports a stream that ends without it as interrupted; an empty model answer is retried once and then replaced by a short apology so a turn never ends silently); the upstream calls are aborted when the browser disconnects (Stop). With accounts enabled every chat route needs a signed-in user (the keys belong to the organisation); without a database only Ollama (`OLLAMA_BASE_URL`, default `http://127.0.0.1:11434`) works and nothing can be saved. `agent.ts` holds the system prompt (it names the user's country, from `@akilimo/shared`'s `COUNTRIES`), `buildConversation` (appends a "everything the farmer has told you so far" list of all user messages to the system prompt and shortens the tool results of earlier turns to 500 chars, and for every provider keeps the history under a rough token budget (`CHAT_CONTEXT_TOKENS`, default 10000, estimated at 3.5 chars per token: older tool results are cut to 120 chars, then the tool exchanges of earlier turns are dropped; user messages and final answers stay), so details are not forgotten; Ollama's `num_ctx` is 16384, `OLLAMA_NUM_CTX` overrides it, because Ollama silently drops the oldest messages past the window) and `runAgent` (max 8 tool rounds, results compacted to 6000 chars); `mcp.ts` connects per request to every enabled registry server with the SDK client (15 s connect timeout, servers that need a key and have none are skipped with a `warning`) and exposes the tools as `<server>__<tool>` functions. **Secrets**: provider keys and upstream MCP server keys live in the tables `llm_providers` and `mcp_server_keys`, encrypted with AES-256-GCM (`secrets/crypto.ts`, format `v1.<iv>.<tag>.<ciphertext>`) under the master key `SECRETS_KEY` (32 bytes, base64 or hex; `openssl rand -base64 32`), which is never stored in the database; without it keys cannot be saved or read, and changing it makes saved keys undecryptable. API responses only carry the last characters (`keyHint`). `store.ts` (`ChatSettings`) resolves a provider to its address and decrypted key. The provider clients are in the **`@akilimo/llm`** package (`packages/llm`): `providers.ts` (the provider table, `listModels`, `chat`, `testProvider`, `pickDefaultModel`) over `openai.ts` (OpenAI-compatible: OpenAI, Gemini, DeepSeek, Groq, Mistral, OpenRouter, OpenCode at `https://opencode.ai/inference/v1` and custom), `anthropic.ts` and `ollama.ts` (native `/api/chat`, `num_ctx` 8192, `think: false` for thinking models; used for the local `ollama` provider and for `ollama-cloud`, which is the same API at `https://ollama.com` with the key as a bearer token, listing a model even if `/api/show` fails), with `toolIds.ts` pairing tool results with calls; it uses only `fetch` and global `crypto`, so the web UI can import its types. The provider-neutral message format (`ChatMessage`, Ollama's shape plus an optional tool-call `id`) is in `@akilimo/shared`.

  Transport is chosen at startup: stdio by default, or HTTP (`transports/http.ts`, Express) serving stateless streamable HTTP at `POST /mcp` (GET/DELETE return 405), legacy SSE at `GET /sse` + `POST /messages?sessionId=`, and `GET /health`. A `Server` instance can only serve one transport, so `index.ts` passes a factory and HTTP creates a server per request (streamable) or per session (SSE). Logs go to stderr (stdout is reserved for the stdio protocol).
- **`src/api/client.ts`** — axios wrapper sending `X-Api-Key` only when one is configured (the routes used are public), 120s timeout (compute calls are slow), normalizing errors to `[Akilimo API <status>] <message>`.
- **`packages/shared`** (`@akilimo/shared`) — Zod schemas (imported from `zod/v4`) mirroring the API's compute validation rules (camelCase section keys, snake_case fields, defaults matching the AKILIMO mobile app's requests), plus the web UI's `MCPEvent` activity type. Consumed as raw TS source (`main: src/index.ts`), no build step; the server's Vite build bundles it in (`ssr.noExternal: true`). `zod` is also a direct server dependency so it resolves from the server's own `node_modules` at runtime.
- **`packages/web`** (`@akilimo/web`) — React 18 + Bootstrap 5.3 MCP client with two modes (navbar switch, remembered in localStorage): **Chat** (default, `ChatView`) and **Advanced** (`ToolRunner`). The server list comes from the gateway (`src/mcp/servers.ts`); `useMcpServers` connects through `/gateway/servers/<id>/mcp`, auto-connects servers that need no key or have a remembered one, and `reload()` drops removed/disabled servers. `src/mcp/keys.ts` remembers upstream keys in localStorage (user's choice; guarded for private mode). `AdminDialog` (admins only, opened from Manage) has the MCP servers tab (add/edit/remove) and the Users tab (roles); registry calls use the session cookie. Presets stay keyed by server id. Accounts: `src/account/` (`api.ts` client for `/api`, `useAccount`), `AccountMenu` (sign-in/sign-up dialog). `ChatView` saves each conversation for signed-in users (created on the first message; appends chained so order is kept), offers History, and resets when the user changes; `App` batches activity saves via `useMcpServers({ onLog })`, loads saved activity on sign-in and clears the feed on sign-out. Guests work as before. **Chat provider and tools**: the chat calls the server (`src/llm/api.ts`: providers, models, test, admin settings and `streamChat`, which reads the NDJSON stream), so the browser holds no provider keys; `useLlm(enabled)` keeps the selected provider and model (remembered in `llm-settings`) and fetches the model list live. With accounts enabled the chat needs a sign-in (`canChat`). `LlmSettings` shows the model list status and, for admins, **Test connection** and an Ollama model download (`pullModel` in `ollama.ts`, streaming `/api/pull` progress through `/proxy/ollama`); keys and addresses are edited by admins in `AdminDialog` > **AI providers** (a key is sent once and is never shown again; the same tab saves the keys of MCP servers that need one). **Guided mode** (`GuidedPanel.tsx`, the default view; a Guided / Ask AI switch in `ChatView`, remembered in `chat-view`) answers from the AKILIMO tools through the browser's MCP connection with no provider: a menu of cassava price, fertilizers and a recommendation form (use case FR); each finished step is passed to `onRecord` and saved by `ChatView` as a `guided` conversation (`mcp/guided.ts` defines `GuidedEntry`), a saved session is shown again by `ReplayPanel`, and History lists the conversations of the mode on screen. **Supported area on the map**: `MapPicker` draws the area where recommendations can be computed (`useCoverage` in `mcp/coverage.ts` fetches `/api/coverage/<country>`, served by `coverage/routes.ts` on the server, which relays the Akilimo API's `/v1/coverage/{country}` and caches it for 30 minutes; `/api/coverage/check` relays the API's point check) and tests every picked point against it in the browser (`geoJsonContains` in `@akilimo/shared`, which mirrors the API's `App\Support\GeoJson`): outside the area it shows a warning at once, turns the marker red, reports `onCoverage(false)`, and the guided forms and the chat's "Send this location" refuse the point. Without an area (an API that has none yet, an unsupported country, an error) there is no overlay and no check, never a block. `ChatView` asks for the country first (`@akilimo/shared`), builds the grouped example questions from it, queues messages sent while an answer is running, and shows server `warning` events (an MCP server that could not be reached). `src/mcp/servers.ts` lists the servers; `src/mcp/useMcpServers.ts` connects with the SDK's `StreamableHTTPClientTransport` through the same-origin `/gateway` path (Vite `server.proxy` in dev, `nginx.conf` in Docker), so servers without CORS support such as Akilimo 2.0 work. `ToolRunner` lists connected servers' tools and renders `SchemaForm`, a generic JSON-Schema form (nullable unions, enums, nested objects, arrays, JSON fallback) so the user enters every input; `ServerPanel` holds the connect switches and the in-memory Akilimo 2.0 key; `ActivityFeed` logs real calls. Any object in a schema with numeric lat/long-named fields gets a Leaflet/OpenStreetMap `MapPicker` (react-leaflet 4, since 5 needs React 19), centred on the object's `country_code` and rounding picks to 4 decimals. A pick also reverse-geocodes the point with OpenStreetMap Nominatim (`zoom=3`, one request per click; respect its usage policy) and writes the ISO code into that object's `country_code`/`countryCode`; the async update goes through a ref to the latest value so it does not undo the lat/long change. `src/mcp/presets.ts` holds per-tool prefill buttons keyed `${serverId}::${toolName}`; the compute presets fill typical defaults without overwriting user input, and load a country's available fertilizers plus middle-band fertilizer (`price_per_bag`) and cassava (`average_price`) prices via `get_reference_data`, skipping 0 and negative placeholder bands.

## Build / deployment gotchas

- The server is built with Vite in library/SSR mode (`packages/server/vite.config.ts`) to `dist/index.cjs`; runtime deps (`@modelcontextprotocol/sdk` and `zod` including their subpaths, `axios`, `express`, `cors`) are externalized, everything else (including `@akilimo/shared`) is bundled. A new runtime dependency must be added both to the server's `package.json` and to the Vite `external` list.
- Two images, both built with the repo root as context: `Dockerfile` (MCP server) and `packages/web/Dockerfile` (static web UI served by unprivileged nginx on 8080; `packages/web/nginx.conf` also proxies `/gateway/` and `/api/` to `akilimo-mcp:3000` and `/proxy/ollama/` to `OLLAMA_UPSTREAM`, resolving via Docker DNS at request time). Compose adds a `db` service (postgres:17-alpine, internal network only, `akilimo-db` volume) created from the same required `DB_*` values the server gets; `akilimo-mcp` waits for it to be healthy; the server image ships the `drizzle/` SQL migrations and applies them itself at start (no database CLI and no `openssl` in the image). `drizzle-orm` and `pg` are in the server's Vite `external` list (and so runtime dependencies); `drizzle-kit` is a dev dependency. `pnpm-workspace.yaml` `allowBuilds` only needs `esbuild`. A `weather-mcp` compose service (`docker/weather-mcp/Dockerfile`) runs the third-party weather MCP server on the internal network. Each installs only its own package via `pnpm install --filter <pkg>...`, but every workspace `package.json` must still be copied for the `--frozen-lockfile` check.
- Images are published to GHCR only (`.github/workflows/docker-publish.yml`: `ghcr.io/iita-akilimo/akilimo-mcp-agent` and `-web`, `latest`/semver/`sha-` tags, PRs build without pushing). Base images are build args (`NODE_IMAGE`, `NGINX_IMAGE`; repo variables of the same names in CI) so they can come from a mirror instead of Docker Hub. Production: service `mcp` in the `akilimo` stack of the `proxy-tool` repo, `127.0.0.1:9101`, Caddy site `akilimo-mcp.akilimo.org` exposing only `/mcp`, `/sse`, `/messages`, `/health`; the API is reached internally at `http://akilimo-api/api`.
- The server image's runner gets its `node_modules` from `pnpm deploy --prod --legacy`, so runtime versions come from `pnpm-lock.yaml`. The pnpm version is pinned by `packageManager` in the root `package.json`. The server exposes `GET /health` (HTTP mode only) for the Docker `HEALTHCHECK`.
- pnpm 12 has written a peer-less `@modelcontextprotocol/sdk` version (`1.32.2` instead of `1.32.2(zod@3.25.76)`) into the web importer, leaving a dangling `node_modules` link and "Cannot find module '@modelcontextprotocol/sdk/…'" in `tsc`. Fix the importer entry in `pnpm-lock.yaml` and run `pnpm install --frozen-lockfile`.
- Open WebUI reaches Ollama on the Docker host via `host.docker.internal` (override with `OLLAMA_BASE_URL`); host Ollama must listen beyond `127.0.0.1` (`OLLAMA_HOST=0.0.0.0`). The compose file expects an external `dokploy-network` Docker network.
- `docs/ANDROID_INTEGRATION.md` explains how the AKILIMO Android app can call this server (protocol details verified against a running server: `Accept` header required, stateless, SSE-framed answers; tool arguments and real responses; OkHttp/Kotlin samples that were not compiled).
- `docs/MCP_CONNECTION_GUIDE.md` documents client configs and the hosted endpoints (Akilimo 1.0, this server, at `akilimo-mcp.akilimo.org/mcp` and `/sse`; Akilimo 2.0 at `mcp.akilimo.org/mcp`).
