# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository. For current status, decisions and open work, see [`docs/HANDOVER.md`](docs/HANDOVER.md).

## What this is

An MCP (Model Context Protocol) server that exposes the Akilimo agricultural API (IITA) as tools for LLM clients (Claude Desktop, Open WebUI + Ollama, etc.), plus a web UI that acts as a real MCP client for it and for the hosted Akilimo 2.0 server. pnpm monorepo, TypeScript throughout.

## Commands

Run from the repo root (pnpm workspace, Node 20+):

```bash
pnpm install
pnpm dev:server      # MCP server over stdio (vite-node packages/server/src/index.ts)
pnpm dev:server:http # MCP server over HTTP on :3001 (streamable HTTP /mcp, SSE /sse); restarts on changes in server/shared/llm src
pnpm dev:web         # web UI at http://localhost:5173; proxies to the server above
pnpm build           # builds all @akilimo/* packages
pnpm start           # node packages/server/dist/index.cjs
pnpm --filter @akilimo/server build   # build only the server
docker-compose up -d # MCP server (127.0.0.1:3080), demo web UI (127.0.0.1:4173), Open WebUI (127.0.0.1:8089)
```

There is no test suite or linter configured.

Copy `.env.example` to `.env`; `config.ts` loads the repo-root `.env` with `process.loadEnvFile` (existing env vars win). Server env vars: `AKILIMO_API_BASE_URL`, `AKILIMO_API_KEY` (optional; needs the API abilities `mcp:verify-keys` to accept users' `ak_…` MCP keys and `reports:read` to renew PDF report links in saved history), `AKILIMO_DEVICE_TOKEN` (optional), `TRANSPORT` (`http`, or legacy `sse`, for HTTP; stdio otherwise; `--http` flag does the same), `PORT` (default 3001 locally; containers set 3000; port 3000 is taken by Dokploy on the dev machine), `ALLOWED_ORIGINS` (comma-separated CORS list and MCP Origin check), `MCP_API_KEYS` (operator MCP client keys; a key is always required), `SHARED_KEY_RATE_PER_MINUTE`/`SHARED_KEY_RATE_PER_DAY` (limit for the shared upstream key), `MCP_RATE_LIMIT`/`MCP_COMPUTE_RATE_LIMIT`, `CHAT_RATE_LIMIT`/`AUTH_RATE_LIMIT` (every rate limit of the server is set in `config.ts`, none is written in a route file), `SSE_MAX_SESSIONS`/`SSE_MAX_SESSIONS_PER_IP`, `DB_*` (accounts PostgreSQL, see below). The web dev proxy reads `AKILIMO_1_MCP_URL` / `AKILIMO_2_MCP_URL`. `docker-compose` additionally requires `WEBUI_SECRET_KEY`.

## Architecture

- **Naming** — this repo's agent is **Akilimo 1.0** (MCP server name and client config key `akilimo-1.0`); the hosted MCP of the Akilimo 2.0 platform is **Akilimo 2.0** (`akilimo-2.0`): streamable HTTP at `https://mcp.akilimo.org/mcp`, partner key required (`Authorization: Bearer` or `X-API-Key`), no CORS support. Use these labels in code and docs.
- **Upstream API** — the Akilimo 1.0 API (Laravel, separate repo `new-akilimo-api`, hosted at `https://api.akilimo.org`, `composer dev` serves it locally on port 8600). Its `routes/api.php`, `app/Rules/*Rules.php` and `app/Data/*Data.php` are the source of truth for endpoints and the compute payload. Where the rules and DTOs disagree (e.g. rules say `unit_price_maize_1`, DTOs read `unit_price_maize1`), follow the DTOs. The R compute service behind it errors with "subscript out of bounds" on values it cannot look up, so shared schema defaults follow what the AKILIMO mobile app sends (`use_case` `FR`, `"NA"` instead of null, yield class instead of 0).
- **`packages/server`** (`@akilimo/server`) — the MCP server, split into modules under `src/`: `index.ts` (entry, picks the transport), `config.ts` (env vars), `server.ts` (builds the low-level `Server` from `@modelcontextprotocol/sdk` and dispatches `ListTools`/`CallTool` to the registry), `tools/` (one file per tool implementing `ToolDefinition` from `tools/types.ts`, registered in `tools/index.ts`), `transports/stdio.ts` and `transports/http.ts`. To add a tool, create a file in `tools/` and add it to the `tools` array; handlers may throw, `server.ts` turns errors into `isError` results. Tools:
  - `get_reference_data` → `GET /v1/{category}` or `/v1/{category}/country/{countryCode}`, all pages merged by `api.getAll` (the API paginates at 50 rows; NG fertilizer-prices has 60). `REFERENCE_CATEGORIES` and `COUNTRY_FILTERABLE` must match the API's public routes; only some categories have a `/country/` route.
  - `get_operation_costs` (`tools/advisory.ts`) → typical land preparation and weeding costs for planting practices advice, ready for `manualCosts`/`tractorCosts`/`weedingCosts`: each is `GET /v1/default-prices` (rows keyed by country, `BU` for Burundi; items `manual_ploughing`, `manual_ridging`, `tractor_ploughing`, `tractor_ridging`, `weeding1`, `weeding2`) when it is believable in US dollars, else the compute service's own default (`BASELINE_COSTS`, copied from `default_lmo_costs` in the `akilimo-recommendations` R repo, `R/AkilimoMain.R`, per acre; it also has harrowing), else the middle band of `GET /v1/operation-costs/country/{code}`, else `null`; each carries `source` and `approx_usd`. The dollar check uses the rough rates in `USD_RATE` (NG 1500, TZ 2600, RW 1450, GH 12, BI 2900 per dollar; refresh them when they drift) and accepts 0.5 to 150 dollars per acre. Tanzanian amounts look huge because the shilling is weak (manual ploughing 175000 is about 67 dollars) and pass; the API's Tanzanian weeding prices (600000 and 450000, about 230 and 170 dollars) fail and the service defaults (60000 and 45000) are used instead. Only Nigeria and Tanzania have data; the compute service ignores harrowing costs in planting practices; Rwanda, Ghana and Burundi need the farmer's own costs.
  - `check_location` (`tools/advisory.ts`) → `GET /v1/coverage/check` of the Akilimo API: is a point inside the area where recommendations can be computed (`covered` true, false, or null when the API has no area for the country or lacks the route; an error from the API becomes `covered: null` so the conversation goes on). The chat instructions tell the model to call it as soon as it has coordinates. The supported area itself is copied from the compute service into the API's `coverage_areas` table (`php artisan coverage:sync`, see that repo's `docs/COVERAGE.md`), and the API also answers 422 to a compute request outside it.
  - **Exchange rates** (`currency/rates.ts`, tool `convert_currency` in `tools/currency.ts`): prevailing rates from the open ExchangeRate-API endpoint (`https://open.er-api.com/v6/latest/USD`, no key, updated daily, cached an hour; `EXCHANGE_RATE_URL` overrides it with the same JSON shape). `convert_currency {amount, from, to | countryCode}` converts through the dollar and answers with the rate and its date; the chat prompt says every amount must be shown in the country's local currency (`Country.currency`) and any other currency converted with this tool, never with a remembered rate. The server also does it itself: `currency/localize.ts` (`localizeNote`) reads foreign amounts in a final answer (`$0.49`, `USD 12`, `15 USD`, `20 euros`, `€5`, `£3`; not the word "pounds", which is also a weight) and appends a line with each in local currency at the live rate and its date, whether or not the model called the tool. The prompt, the web fallback and the web enrichment also ask for a short Markdown summary table of web findings (item, local price, original price, source url, as-of date); that part is up to the model. `get_operation_costs`' dollar sanity check also uses the live rate of the country's currency; the old approximate `USD_RATE_FALLBACK` is only used when the rates cannot be read. Only currency codes and amounts leave the server for this, no user data.
  - **Cassava selling unit** — farmers quote cassava per kg, per 50 or 100 kg bag or per tonne, so the price is never assumed to be per tonne: the units come from the API (`cassava-units` via `get_reference_data`, `useSellUnits` in `GuidedParts.tsx`), `CassavaPriceInput` (guided forms, chat field form) takes the price and its unit and converts the number when the unit changes (same rate: 15,000 per tonne = 750 per 50 kg = 15 per kg), and the compute request gets `cassava.unit_price` per that unit with `unit_weight` in kg. The plausibility check scales the price back to per tonne first (`PriceHint` `unitWeight`). The chat prompt asks for the unit and the field message carries `per <unit> (unit_weight <kg>)`.
  - **Countries** — the supported countries are not written in the code: they come from the Akilimo API (`GET /v1/countries`, the active ones in `sort_order`; its resource also sends `latitude`, `longitude` and the bounding box). `countries/list.ts` (`fetchCountries`, cached one minute, empty answers not cached; the web hook also refetches when the tab is shown after a minute, so an activated country appears quickly; a country with no cassava price list yet, like a newly activated one, has no currency, and the local-currency conversion is skipped for it until the API gives it one) adds each country's currency from its cassava price list, and serves the tool `get_countries` and the relay `GET /api/countries`; there is no built-in fallback list, so the web UI (`useCountries` in `mcp/countries.ts`) shows an error with a Retry button when the API cannot be reached. `@akilimo/shared` only has the `Country` type, `findCountry(list, code)` and `parseCountries`. The chat prompt names the countries from the list, the map starts on the country's position and fits its supported area (or bounds), the example questions use the country name and the next countries in the list, and currencies come from `Country.currency`. Still keyed by country code in the code, because they are compute-service rules or data and not the supported list: `INTERCROP_CROPS`/`intercropCrop` (second crop for intercropping), `BASELINE_COSTS` and `USD_RATE` in `tools/advisory.ts`.
  - **Crops** — the list of crops lives in the Akilimo API (table `crops`, `GET /v1/crops` and `/v1/crops/country/{code}`, managed in its admin area under Supporting Data > Crops; `advice_available` says whether recommendations exist, `countries` null = everywhere; only cassava is seeded, by the migration). `get_reference_data` accepts the category `crops`, and the tool `get_crops` (`tools/crops.ts`, optional `countryCode`) returns the list with `advice_available`. Both it and the web relay `GET /api/crops?country=` (`crops/routes.ts`, an API answer is cached 5 minutes, a fallback is not) use `fetchCrops` in `crops/list.ts`, which falls back to `DEFAULT_CROPS` = cassava from `@akilimo/shared` when the API has no route (not deployed or migrated yet) or fails, with `source` saying which; the web UI's crop selector (`useCrops` in `mcp/crops.ts`, choice remembered in localStorage `akilimo-crop`) sits next to the country select, sends `crop {key, name, advice_available}` with every chat request, and for a crop without advice hides the advice menu, cards and dropdown and tells the model (system prompt `cropNote`) never to call `compute_recommendations`. The compute payload has no crop field yet, so a new crop with advice needs the R service first.
  - `get_market_options` (`tools/market.ts`) → where cassava roots sell in a country: the open market (`/v1/cassava-prices/country/{code}` bands and typical price) next to the starch factories (`/v1/starch-factories/country/{code}` joined with the rows of `/v1/starch-prices` by `factory_name`), each with its price classes by minimum starch percent, price range and the percentage of its best price over the open-market typical price, plus `starch_prices_as_of`/`age_days`/`stale` (over 90 days). The API keeps no price history (all starch rows share one `updated_at`), so there is no trend or outlook, and the starch rows' `currency` is empty (the cassava price currency is used). In the R service `saleSF`/`nameSF` (`yieldInfo.sell_to_starch_factory`, `starch_factory_name` = the factory's `factory_name` key) make FR/PP/IC use the factory's HIGHEST price (`get_cassUPUW`), which assumes high-starch roots; only the scheduled planting advice (SP) prices by estimated starch content. The web UI shows it as the guided "Where to sell" screen (`MarketView`, action `market`, saved and replayed), a `SellSelect` in every advice form and the chat's field form, and the chat advice option, example question and prompt rules.
  - **Soil and climate** (`tools/environment.ts`, `geo/soil.ts`, `geo/climate.ts`; no key, no data sent but the coordinates): `get_soil_profile {lat, lon}` reads ISRIC SoilGrids (`SOILGRIDS_URL`, default `https://rest.isric.org/soilgrids/v2.0`; pH, organic carbon, nitrogen, clay/silt/sand at 0-5, 5-15 and 15-30 cm, values scaled by the service's `d_factor`, plus the topsoil's pH class and USDA texture class; 3 attempts because the public service often answers 503, 24 h cache per ~110 m) and `get_climate_summary {lat, lon}` reads NASA POWER monthly data (`POWER_URL`; twenty complete years averaged into a typical year: rainfall mm and mean temperature per month, annual rainfall, wettest/driest month, months with at least 100 mm; 7 day cache). Both are context only (the compute payload takes no soil or climate input, the prompt says so) and answer `available: false` with a message instead of an error when the service fails, so the conversation goes on. A self-hosted SoilGrids copy needs the same `/properties/query` route.
  - **Akilimo 1.0 and 2.0 side by side** (fertilizer advice only; `@akilimo/shared` `akilimo2.ts`, `chat/dual.ts`, `Akilimo2Result.tsx`): when a connected server other than the one that computes offers Akilimo 2.0's `get_recommendation` (crop, lat, lon, country, optional `context` with area, `areaUnit`, `max_investment`, `fertilizers`, `risk_profile`, ...; answer: N/P/K rates and products, a yield distribution, net return and chance of loss, a reasoning line, the model and its release status, flags), a `compute_recommendations` request is also put to it at the same time. `akilimo2Args` builds 2.0's call from the 1.0 request: only crop `cassava`, the field's place (`map_lat`, `map_long`, `country_code`) and size/unit; the farmer's fertilizer prices, budget, yield class and risk attitude are NOT sent, so 2.0 answers with its own prices (its money is per hectare, in USD, and `prices` may say `default-placeholder`), and the UI and the prompt say so. `summarizeAkilimo2` keeps the figures and turns its flags into plain warnings (low confidence, outside its model's range, nutrient imbalance, model not yet released, placeholder prices). **Chat**: `recommendOnBoth` (called from `chat/routes.ts` for the tool `compute_recommendations`) runs both calls in parallel (60 s limit for 2.0, each counted against the shared-key allowance) and returns ONE tool result `{akilimo_2_0: {figures | error, note}, akilimo_1_0}` (2.0's short summary first, so truncation to 6000 characters cannot cut it off); a failure, timeout or refused call of 2.0 only puts an `error` in its part and never hides the 1.0 answer; the system prompt asks the model to show the two in one answer under "Akilimo 1.0" and "Akilimo 2.0", never mix or average them, state 2.0's warnings and convert its USD. **Guided**: `RecommendScreen` (`withSecond` = a connected server other than the computing one lists `get_recommendation`) awaits both calls together (`askSecond`, 60 s limit) and shows them at once as two labelled sections; the result is saved in the step as `GuidedEntry.second` (`{summary}` or `{error}`), so a replayed session shows both. The 2.0 card has a "Show money in: US dollars / Local currency" switch (live screens and replays; `convert_currency` with 1 USD gives the live rate, which is applied to the net return and shown with its date; the dollar amounts in 2.0's reasoning sentence ("508 USD", "$508") are converted at the same rate. Servers are matched by their tools, never by id (a dev registry may call the 1.0 server `akilimo-mcp-dev`). Not covered: planting practices, dates and intercropping stay on 1.0 only (2.0 has no matching tool known to be equivalent).
  - **Missing prices and costs** (`find_missing_prices`, `tools/missing-prices.ts`, `prices/benchmark.ts`, `prices/search.ts`): for the components that have NO default it suggests a value. It first finds the gaps with the tools the rest of AKILIMO uses (`get_fertilizer_options` without `typical_price_per_bag`, `get_cassava_price` without a typical price, `get_operation_costs` with a null cost; the maize and sweet potato prices of intercropping only when named in `items`), then offers (1) the **World Bank benchmark** (`prices/benchmark.ts`: the monthly "Pink Sheet" Excel file, whose address changes every month and is found on `worldbank.org/en/research/commodity-markets`, or set `FERTILIZER_BENCHMARK_URL`; read with `fflate` and a small XML reader, sheet "Monthly Prices", columns Urea, DAP, TSP, Potassium chloride and Maize in nominal US dollars per tonne; cached a day; the API of the World Bank has no fertilizer series) turned into an indicative price per bag or per 100 kg of grain in the local currency (`convert_currency` rate), always labelled as a world market price before transport and the dealer's margin, and (2) only with `onlineSearch: true`, a web search per gap (at most 6 a call, 4 hits each) whose snippets are read for amounts next to the currency (`amountsIn`); a web amount only becomes the suggestion when a benchmark exists to check it against (between half and eight times), otherwise the amounts and links are candidates for the farmer to judge. Cassava, sweet potato and operation costs have no benchmark, so they only get web results. It never changes anything: every result is a suggestion with `basis`, source, date and a note. **Web search stays the user's choice**: the tool's `onlineSearch` defaults to false, `chat/routes.ts` overrides it with the user's own web search setting (`find_missing_prices` never searches for a user who has it off), and the search service is the admin's (`setSearchConfigResolver` in `index.ts`, SEARCH_* as the fallback). The chat prompt tells the model to call it for gaps, to present the suggestion as unconfirmed with source and date, and never to put it in `compute_recommendations` before the farmer confirms. The web UI's `PriceSuggest` ("Suggest a price" under an empty price or cost, with "Use this price") is in the guided fertilizer, cassava price and planting-practice cost fields and in the chat's fertilizer chooser; costs and the cassava price show it only when the user has web search on; the chat's field and practices forms leave it to the assistant.
  - `get_crop_prices`, `check_price`, `get_investment_options`, `fertilizer_plan` (`tools/farm-inputs.ts`): `get_crop_prices` gives the second crop of intercropping (NG maize as `fresh_cob`, the API's `cob`, or `grain`; TZ sweet potato `tubers`) with typical price, unit weight (grain's 100 kg is an assumption) and allowed range, ready for `compute_request.maize`/`sweetPotato`; `check_price` tests a price (cassava, maize cob/grain, sweet potato, a fertilizer by key) against the lists' `min_allowed_price`/`max_allowed_price` (0/-1 = no limit; `ok` null when no range is known) and the web UI shows it as a non-blocking warning (`PriceHint`); `get_investment_options` lists the budget choices per area unit and, given the field size, as totals for the field (`max_investment_for_field`; compute's `maxInvestment` is for the WHOLE field, 0/omitted = no limit); `fertilizer_plan` turns `fertilizer_rates` (kg for the whole field) into bags (rounded to half bags like the R service, `planBags` in `@akilimo/shared`) and cost, and the web UI shows the same table under the FR result (`BagPlan`, also in replay).
  - `get_fertilizer_options` / `get_cassava_price` (`tools/advisory.ts`) → compact views (≈3 KB instead of ≈28 KB) with sorted price bands and a middle-band "typical" price, skipping 0/negative placeholder bands. Raw lists overflow small local models, which then guess; prefer these in LLM prompts.
  - **PDF reports** (`tools/report.ts` `get_recommendation_report`, `ReportLink.tsx`): the compute service (R, `returnPdf`) makes a PDF report for every recommendation; the Akilimo API keeps it as long as its recommendation history (under the computation's `request_id`) and answers with `report {id, url, expires_at, files}`, a link signed relative to the site and put on its `APP_URL` that lasts 7 days (no key needed; see that repo's `docs/ARCHITECTURE.md`, "PDF reports"). Saved history keeps working: `GET /api/reports/:id/link` (signed-in user, `accounts/routes.ts`) gets a new link from the API's `GET /v1/recommendations/reports/{id}`, only for a report whose id appears in one of the user's own saved messages (a guided step's `data` or a chat's tool result); it needs this server's `AKILIMO_API_KEY` to have the `reports:read` ability (503 and a log line otherwise). In the web UI `openReport` (`ReportLink.tsx`) opens a link that is still good, or renews an expired one first (guided results, replays, and report links in chat answers). `compute_recommendations` puts `report` FIRST in its result so the chat's 6000-character cut keeps it, the chat prompt tells the model to end the answer with a "Download the full report (PDF)" link to that exact url and its expiry date (and not to call the report tool), and the chat's Markdown links open in a new tab. `get_recommendation_report {url}` is for MCP clients that can show files: it accepts only the path `/v1/recommendations/reports/<uuid>/<name>.pdf` with a `signature`, ignores the link's host and fetches it from `AKILIMO_API_BASE_URL` (`api.getFile`), and answers with the PDF as an embedded `resource` (`application/pdf`, base64) plus the link; a 403/404 becomes "the link has expired". The guided fertilizer and advice results (`RecommendationResult`, `AdviceResult`, also in replays) show a "Download the report (PDF)" button with the expiry date, or "A new link is made when you open it" for an expired one. A report shows the farmer's name and farm, so the API only hands a cached report to a request with the same personal details.
  - `compute_recommendations` → `POST /v1/recommendations/compute` with `{ user_info, compute_request, fertilizer_list }`. The tool's JSON schema is generated from the shared Zod schema (`z.toJSONSchema(..., { io: "input" })`), so defaulted fields are optional for the model. `user_info` is filled with an anonymous `DEFAULT_USER_INFO` that callers may override. Its `risk_attitude` (0 careful, 1 balanced, 2 risk-taking; `min_nr_multiplier` in the R repo's `misc.R`: fertilizer is only advised when the extra income is at least 1.8, 1.0 or 0.2 times its cost) defaults to 1, because 0 made "fertilizer does not pay" the usual answer; the guided forms (`RiskSelect`) and the chat's field form send it.
  
  **MCP gateway** (`src/gateway/`, HTTP mode only, mounted at `/gateway`): `registry.ts` keeps the shared MCP server list in the table `mcp_servers` (`DbRegistry`: filled on the first start with an empty table from the old registry file at `GATEWAY_DATA_FILE` if there is one, otherwise with the akilimo-1.0 and akilimo-2.0 defaults; a saved key follows a server whose id changes and is deleted with it) or, without a database, read-only from that file or the defaults (`FileRegistry`); entries are zod-validated (id slug, label, description, http(s) url, auth none/bearer/header, enabled) and the interface is async; seeded with akilimo-1.0 → `http://127.0.0.1:$PORT/mcp` and akilimo-2.0; atomic temp-file writes; zod-validated entries: id slug, label, description, http(s) url, auth none/bearer/header, enabled). `routes.ts` serves the public list (`editable` = requester is an admin), add/edit/remove for signed-in users with the `admin` role (session loaded only on registry routes, JSON-only writes; without a database it is read-only, because registering URLs is an SSRF vector), an admin-only `POST /gateway/test` (`test.ts`: connects with the SDK client using the entry's URL and key setting, lists tools, 20 s timeout, turns fetch/HTML/JSON error bodies into readable messages; nothing saved), and a streaming streamable-HTTP proxy at `/gateway/servers/:id/mcp` that forwards MCP headers and maps the browser's `X-Mcp-Key` to the entry's auth. **Own and shared keys**: a user's own key always wins and is never limited. A signed-in user saves it in their ACCOUNT (table `user_mcp_keys`, migration `0008`, encrypted with AES-256-GCM like the other secrets; `GET /chat/keys`, `PUT/DELETE /chat/keys/:id`; only the last characters ever come back; the panel's `KeyBlock` offers "Save to my account", "Replace", "Remove" and, for a key that was only in the browser, "Move it to my account"), so it survives signing out and follows them to other devices; without an account (guests, a server with no database) it is only remembered in the browser (localStorage) and sent per request in `X-Mcp-Key`. The gateway and the chat resolve a key in this order: the request's own (the header, or `keys` in `POST /chat`), the user's saved key, then the shared key; `GET /gateway/servers` also returns `own_keys` (server id to last characters) so the panel connects without asking. Without a key of their own, a signed-in user is served with the shared key an admin saved for that server (`mcp_server_keys`, Manage > AI providers > Shared keys; `GET /gateway/servers` lists the ids that have one as `shared_keys`, only for signed-in users, never the key; the web panel connects such servers by itself and says which key is used, `refreshAccess` in `useMcpServers.ts` reconnects after sign-in or sign-out) and the gateway adds it upstream; guests get none. Calls through the shared key are counted per user (`gateway/quota.ts` `CallQuota`, fixed windows in memory, only JSON-RPC `tools/call` counts, `SHARED_KEY_RATE_PER_MINUTE` default 20 and `SHARED_KEY_RATE_PER_DAY` default 300; over the limit the proxy answers 429 with `Retry-After` and a JSON-RPC error telling the user to wait or add their own key) and admins are exempt. The chat does the same: `POST /chat` takes the user's own keys in `keys` (used instead of the shared key, not stored, never limited) and tool calls through a shared key count against the same quota unless the user is an admin.

  **Accounts** (`src/accounts/`, `src/db/`, HTTP mode only, mounted at `/api`): **Drizzle ORM** (`drizzle-orm` + `pg`, plain npm packages with no downloaded engines; it replaced Prisma, whose engine download from `binaries.prisma.sh` failed in Docker builds on a WSL network) with **PostgreSQL only**, configured by Laravel-style `DB_HOST`/`DB_PORT` (5432)/`DB_DATABASE` (`akilimo_mcp`)/`DB_SCHEMA` (`public`)/`DB_USERNAME`/`DB_PASSWORD`; `DB_CLIENT` (or `DB_CONNECTION`) is optional and must be `pgsql`. `db/settings.ts` parses them, treating blank values as unset; it returns `null` when `DB_HOST` is unset (guest-only HTTP mode and stdio mode keep working, `GET /api/auth/status` reports `enabled: false` and everything else is 503) and throws a clear error when a host is set without a username or password. Its `connectionString` (`postgresql://`, credentials URL-encoded) is only for drizzle-kit's database commands; the server itself passes separate fields to `pg`. Schema: `src/db/schema.ts` (table, index and constraint names match what Prisma created, so databases from either tool are the same); migrations: SQL files in `packages/server/drizzle/` (create with `pnpm db:generate`, which needs no database, review the SQL, commit it with `drizzle/meta/`; never edit applied ones; `drizzle.config.ts` configures drizzle-kit). `db/index.ts` `connectDb` opens a `pg` Pool with separate fields (no URL escaping) and runs the migrator (`drizzle-orm/node-postgres/migrator`, folder `./drizzle` relative to the working directory or `DB_MIGRATIONS_DIR`, bookkeeping table `__drizzle_migrations` in `DB_SCHEMA`, default `public`), so every start, `pnpm db:migrate` (`--migrate`) and `--seed-admin` bring the schema up to date and an unreachable or failing database stops start-up with a clear message. `0000_baseline.sql` is hand-edited to be idempotent (`IF NOT EXISTS`, guarded constraints) so databases created by Prisma are adopted; the leftover `_prisma_migrations` table is unused. Queries use the core builder (`db.select().from(...)`), unique violations are PostgreSQL error 23505 (check `error.cause` too), and malformed UUID path ids are answered with 404 before querying. API responses keep snake_case fields. `auth.ts`: scrypt password hashes (`scrypt$N$r$p$salt$hash`), 32-byte session tokens in the HttpOnly SameSite=Lax `akilimo_session` cookie (Secure over HTTPS; `trust proxy` set), only SHA-256 of tokens stored, JSON-only writes as CSRF guard, in-memory rate limit on signup/login. **Usernames**: `users.username` is unique and lowercase (`UsernameSchema` in `auth.ts`: 3-30 of `a-z 0-9 . _ -`, never `@`); signup requires it and returns a 409 that says whether the email or the username is taken; login takes `login` (an email if it contains `@`, otherwise a username; the old `email` field still works); `USER_SELECT` is the user shape in every response. The username column was originally added to existing Prisma-era accounts by a backfill from the email's local part (`usernameFromEmail` follows the same rules). `routes.ts`: signup/login/logout/status, conversations (+ messages, storing the full model history incl. `tool_calls`/`tool_name`; `conversations.mode` is `ai` or `guided`, `GET /api/conversations?mode=` filters, and a guided step is one message with role `tool` whose `messages.data` jsonb holds `{action, country, title, tool, request, result}`, capped at 500 KB) and activity, every query scoped by `user_id`; admin-only `GET /api/admin/users` and `PATCH /api/admin/users/:id` (role change; refuses to demote the last admin). **Roles**: `users.role` is a PostgreSQL enum named `Role` (`user` default, `admin`); `requireAdmin` in `auth.ts` guards admin actions. `seed.ts` ensures an admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD`/`ADMIN_NAME`/`ADMIN_USERNAME` (optional; derived from the email, with a suffix if taken) on every HTTP start and via `--seed-admin` (`pnpm seed:admin`): creates if missing, promotes an existing account, never changes a password or username, and refuses an `ADMIN_USERNAME` that belongs to another account.

  **Remembered farm details** (`FarmProfileSchema` in `@akilimo/shared` `farm.ts`; table `farm_profiles`, migration `0009_farm_profiles.sql`, one row per user and country; `GET/PUT/DELETE /api/farm-profiles/:country`, signed-in user only, validated again on every read and write): what the forms already learned about a field in a country (location, size and unit, yield class, risk attitude, cassava price, selling unit and factory, date windows, the fertilizers the farmer can buy with their prices; never dates, keys or anything else) so it is not typed again. `useFarmProfile` (`web/src/mcp/farmProfile.ts`) loads it from the account and, for a guest or a server without accounts, from the browser (localStorage `farm-profile-<CC>`, the same schema); the guided fertilizer form (`RecommendScreen`), the practices/dates/intercropping forms (`AdviceScreen`) and the chat's field form (`FieldPicker`) fill in from it and save when a step is finished. **The location (latitude and longitude) is handled by `MapPicker` itself**, so every map has it, including the chat's map dialog and the generic tool forms of Advanced mode: each pick is saved at once (rounded to 4 decimals), and a map with no point yet starts at the remembered one (only a real 2-letter country code is used as the key). All of this happens only when the "Remember my farm details" box (`RememberBar`, on by default, the choice kept in the browser) is ticked; "Forget them" erases the saved details. A location is personal data: it stays with the account, is not sent anywhere else and goes with the account when it is deleted. **Key tracking** (migration `0007_key_tracking.sql`): table `key_events` is a trail of what admins did with keys (`mcpkeys/events.ts`: who created, changed or revoked an admin-issued client key, who saved or removed a shared upstream key, and when; never a key, only names, hints and limits; `GET /api/admin/key-events`, admin only, no screen yet). `mcp_client_keys.use_count` counts the requests made with a client key (written together with `last_used_at`, at most once a minute); `mcp_server_keys.updated_by` is the admin who saved the key, while `last_used_at`/`use_count` on it exist but are not written yet; `user_mcp_keys.last_used_at` is set when a user's saved key is used for a tool call.

  **Chat** (`src/chat/`, HTTP mode only, mounted at `/chat`): the model calls and MCP tool calls of the web chat run on the server, so the browser only sends the conversation. `routes.ts`: `GET /chat/providers` (signed-in users see the providers that are on and set up; admins see every provider with `configured`, `baseUrl`, `keyHint`), `GET /chat/models/:provider` (live list plus the default model), admin-only `POST /chat/test`, `PUT /chat/admin/providers/:id` (`apiKey`, `clearKey`, `baseUrl`, `enabled`), `GET/PUT/DELETE /chat/admin/server-keys/:id`, and `POST /chat`, which validates `{provider, model, country, messages}`, runs the agent loop and streams newline-delimited JSON events (`message`, `step`, `warning`, `error`, `ping`, `done`; a `ping` every 15 s keeps proxies from closing a silent stream, every finished answer ends with `done` and the web client reports a stream that ends without it as interrupted; an empty model answer is retried once and then replaced by a short apology so a turn never ends silently); the upstream calls are aborted when the browser disconnects (Stop). With accounts enabled every chat route needs a signed-in user (the keys belong to the organisation); without a database only Ollama (`OLLAMA_BASE_URL`, default `http://127.0.0.1:11434`) works and nothing can be saved. `agent.ts` holds the system prompt (it names the user's country, from `@akilimo/shared`'s `COUNTRIES`), `buildConversation` (appends a "everything the farmer has told you so far" list of all user messages to the system prompt and shortens the tool results of earlier turns to 500 chars, and for every provider keeps the history under a rough token budget (`CHAT_CONTEXT_TOKENS`, default 10000, estimated at 3.5 chars per token: older tool results are cut to 120 chars, then the tool exchanges of earlier turns are dropped; user messages and final answers stay), so details are not forgotten; Ollama's `num_ctx` is 16384, `OLLAMA_NUM_CTX` overrides it, because Ollama silently drops the oldest messages past the window) and `runAgent` (max 8 tool rounds, results compacted to 6000 chars; a tool call a small model writes as JSON text, e.g. `{"tool": "...", "arguments": {...}}` in a code block, is run as a real call by `textcalls.ts` (a mistyped server prefix is matched on the tool's own name) and the JSON and the prose around it are not shown, only the expandable tool step; an identical call repeated in a turn is not run again and gets the first result with a note to answer from it); **Web search** (`chat/websearch.ts`, optional): managed by admins in Manage > AI providers > Web search (table `web_search_settings`, one row `default`: provider `brave`, `tavily`, `serper` (Serper.dev, Google results) or `searxng`, the key encrypted like provider keys, the SearXNG address, an on/off switch; `GET/PUT /chat/admin/web-search`, `POST /chat/admin/web-search/test` runs one real search; `ChatSettings.webSearchConfig` resolves it), with the `SEARCH_PROVIDER`/`SEARCH_API_KEY`/`SEARCH_URL` variables as the fallback when no admin setting exists (an admin setting, including "off", wins); `GET /chat/capabilities` says whether it is usable, the web UI then shows a globe toggle that is OFF by default, and only a user whose profile has web search on (or, without accounts, a chat request with `webSearch: true`), with a configured service, gives the model the `web__web_search` tool (5 results of title, url and snippet, 15 s timeout, 200 character query) and the prompt rules (untrusted content, no personal details, cite the url, never recommendations from the web; plus two steps enforced in code in `runAgent` (`agent.ts`) and not left to the model: a fallback (a final answer that gives up, matched by `NOT_FOUND` such as "does not have" or "no data", is hidden and the model is sent back once to call `web__web_search`; valid answers such as "fertilizer not recommended" do not match) and an enrichment (after a successful `compute_recommendations`, one more step adds a separate "From the web" section with urls and prices converted to the local currency; "No extra web information found." is not shown). The switch is a profile setting for signed-in users (`users.web_search`, migration `0005_user_web_search.sql`, `PATCH /api/auth/preferences`, a "Web search on/off" button in the account menu and the globe button in the chat, applies to every conversation and device, and the server uses the profile, not the request); without accounts the request's `webSearch` is used and it resets with each new conversation. `mcp.ts` connects per request, with the SDK client, to the enabled registry servers the user has switched on (`POST /chat` takes their ids in `servers`, sent by the web UI from the connection switches of the MCP servers panel; without the field every enabled server is used, and with an empty list the chat gets a `warning` and no tools) (15 s connect timeout, servers that need a key and have none are skipped with a `warning`) and exposes the tools as `<server>__<tool>` functions. **Secrets**: provider keys and upstream MCP server keys live in the tables `llm_providers` and `mcp_server_keys`, encrypted with AES-256-GCM (`secrets/crypto.ts`, format `v1.<iv>.<tag>.<ciphertext>`) under the master key `SECRETS_KEY` (32 bytes, base64 or hex; `openssl rand -base64 32`), which is never stored in the database; without it keys cannot be saved or read, and changing it makes saved keys undecryptable. API responses only carry the last characters (`keyHint`). `store.ts` (`ChatSettings`) resolves a provider to its address and decrypted key. The provider clients are in the **`@akilimo/llm`** package (`packages/llm`): `providers.ts` (the provider table, `listModels`, `chat`, `testProvider`, `pickDefaultModel`) over `openai.ts` (OpenAI-compatible: OpenAI, Gemini, DeepSeek, Groq, Mistral, OpenRouter, OpenCode at `https://opencode.ai/inference/v1` and custom), `anthropic.ts` and `ollama.ts` (native `/api/chat`, `num_ctx` 8192, `think: false` for thinking models; used for the local `ollama` provider and for `ollama-cloud`, which is the same API at `https://ollama.com` with the key as a bearer token, listing a model even if `/api/show` fails), with `toolIds.ts` pairing tool results with calls; it uses only `fetch` and global `crypto`, so the web UI can import its types. The provider-neutral message format (`ChatMessage`, Ollama's shape plus an optional tool-call `id`) is in `@akilimo/shared`.

  Transport is chosen at startup: stdio by default, or HTTP (`transports/http.ts`, Express) serving stateless streamable HTTP at `POST /mcp` (GET/DELETE return 405), legacy SSE at `GET /sse` + `POST /messages?sessionId=`, and `GET /health`. **Hardening** (`transports/guards.ts`): `checkAccess` guards `/mcp` and `/sse`: a key sent as `Authorization: Bearer` or `X-API-Key` (like Akilimo 2.0's partner keys) must be valid (401 otherwise) and then skips the Origin check; valid keys are the operator's `MCP_API_KEYS` (`staticKeyVerifier`, SHA-256 + `timingSafeEqual`) and **Akilimo API MCP keys** (`api/keys.ts` `akilimoKeyVerifier`: `ak_…` keys users create in the API's playground with type "MCP key", ability `mcp:use`; checked with `POST /v1/mcp/verify-key` of `new-akilimo-api`, which needs this server's `AKILIMO_API_KEY` to have `mcp:verify-keys`; answers cached 60 s valid / 30 s invalid by SHA-256; only used when `AKILIMO_API_KEY` is set; an API error gives 503). A key is ALWAYS required (there is no switch), and three kinds are accepted: keys admins issue in the database (below), the operator keys of `MCP_API_KEYS`, and the `ak_` keys users create in the Akilimo API playground. **Admin-issued keys** (`mcpkeys/store.ts` `ClientKeyStore`, table `mcp_client_keys`, migration `0006_mcp_client_keys.sql`; `GET/POST /api/admin/mcp-keys`, `PATCH/DELETE /api/admin/mcp-keys/:id`, admin only; web: Manage > MCP keys, `McpKeysTab.tsx`): a key is `amk_` + 32 random bytes (base64url), shown ONCE in the create answer, only its SHA-256 is stored with a hint (`amk_…` + last 4 characters); a key has a name, optional expiry, optional own limits `per_minute`/`per_day` (null = `MCP_KEY_RATE_PER_MINUTE` default 60 / `MCP_KEY_RATE_PER_DAY` default 5000), `last_used_at` (written at most once a minute) and is revoked (not deleted, so the list keeps its history) at once; `checkAccess` counts every request of such a key in a `CallQuota` and answers 429 with `Retry-After` over the limit, while keys from `MCP_API_KEYS` and the API only have the per-IP limit. A request without a key gets 401 with a `WWW-Authenticate: Bearer` challenge; only loopback (the server's own chat and gateway) is exempt, and it still gets the Origin check (a browser `Origin` outside `ALLOWED_ORIGINS` gets 403, the spec's DNS-rebinding check; no `Origin` passes). At start the server logs a warning when neither `MCP_API_KEYS` nor `AKILIMO_API_KEY` is set, because then no outside client can be accepted. `/messages` is only rate limited, as its session id comes from an `/sse` that passed. The MCP endpoints are rate limited per client IP (`MCP_RATE_LIMIT`, default 120/min, and `MCP_COMPUTE_RATE_LIMIT`, default 10/min for `compute_recommendations` on `/mcp`; loopback, i.e. the server's own chat and gateway calls, is exempt; `rateLimit` in `accounts/auth.ts` takes the JSON-RPC body), SSE sessions are capped (`SSE_MAX_SESSIONS` 200, `SSE_MAX_SESSIONS_PER_IP` 5) and closed after 30 idle minutes; every response gets nosniff, `X-Frame-Options: DENY`, `default-src 'none'` CSP, no-referrer and HSTS over HTTPS, `X-Powered-By` is off, malformed JSON gets a JSON-RPC `-32700` and other errors JSON without internals. Tool errors: only a `ToolError` (tools' input checks, `[Akilimo API …]` errors from `api/client.ts`) reaches the caller; anything else is logged and answered generically, and API 500s and unreachable-API errors are reworded so internal hosts and SQL never leak. `server.ts` declares only the `tools` capability, marks every tool `readOnlyHint`/`idempotentHint`/`openWorldHint` (a tool may override via `annotations`) and reports the version from `package.json`. A `Server` instance can only serve one transport, so `index.ts` passes a factory and HTTP creates a server per request (streamable) or per session (SSE). Logs go to stderr (stdout is reserved for the stdio protocol).
- **`src/api/client.ts`** — axios wrapper sending `X-Api-Key` only when one is configured (the routes used are public), 120s timeout (compute calls are slow), normalizing errors to `[Akilimo API <status>] <message>`.
- **`packages/shared`** (`@akilimo/shared`) — Zod schemas (imported from `zod/v4`) mirroring the API's compute validation rules (camelCase section keys, snake_case fields, defaults matching the AKILIMO mobile app's requests), plus the web UI's `MCPEvent` activity type. Consumed as raw TS source (`main: src/index.ts`), no build step; the server's Vite build bundles it in (`ssr.noExternal: true`). `zod` is also a direct server dependency so it resolves from the server's own `node_modules` at runtime.
- **`packages/web`** (`@akilimo/web`) — React 18 + Bootstrap 5.3 MCP client with two modes (navbar switch, remembered in localStorage): **Chat** (default, `ChatView`) and **Advanced** (`ToolRunner`). The server list comes from the gateway (`src/mcp/servers.ts`); `useMcpServers` connects through `/gateway/servers/<id>/mcp`, auto-connects servers that need no key or have a remembered one, and `reload()` drops removed/disabled servers. `src/mcp/keys.ts` remembers upstream keys in localStorage (user's choice; guarded for private mode). `AdminDialog` (admins only, opened from Manage) has the MCP servers tab (add/edit/remove) and the Users tab (roles); registry calls use the session cookie. Presets stay keyed by server id. Accounts: `src/account/` (`api.ts` client for `/api`, `useAccount`), `AccountMenu` (sign-in/sign-up dialog). `ChatView` saves each conversation for signed-in users (created on the first message; appends chained so order is kept), offers History, and resets when the user changes; `App` batches activity saves via `useMcpServers({ onLog })`, loads saved activity on sign-in and clears the feed on sign-out. Guests work as before. **Chat provider and tools**: the chat calls the server (`src/llm/api.ts`: providers, models, test, admin settings and `streamChat`, which reads the NDJSON stream), so the browser holds no provider keys; `useLlm(enabled)` keeps the selected provider and model (remembered in `llm-settings`) and fetches the model list live. With accounts enabled the chat needs a sign-in (`canChat`). `LlmSettings` shows the model list status and, for admins, **Test connection** and an Ollama model download (`pullModel` in `ollama.ts`, streaming `/api/pull` progress through `/proxy/ollama`); keys and addresses are edited by admins in `AdminDialog` > **AI providers** (a key is sent once and is never shown again; the same tab saves the keys of MCP servers that need one). **Guided mode** (`GuidedPanel.tsx`, the default view; a Guided / Ask AI switch in `ChatView`, remembered in `chat-view`) answers from the AKILIMO tools through the browser's MCP connection with no provider: a menu of cassava price, fertilizers and a recommendation form (use case FR); each finished step is passed to `onRecord` and saved by `ChatView` as a `guided` conversation (`mcp/guided.ts` defines `GuidedEntry`), a saved session is shown again by `ReplayPanel`, and History lists the conversations of the mode on screen. **Supported area on the map**: `MapPicker` draws the area where recommendations can be computed (`useCoverage` in `mcp/coverage.ts` fetches `/api/coverage/<country>`, served by `coverage/routes.ts` on the server, which relays the Akilimo API's `/v1/coverage/{country}` and caches it for 30 minutes; `/api/coverage/check` relays the API's point check) and tests every picked point against it in the browser (`geoJsonContains` in `@akilimo/shared`, which mirrors the API's `App\Support\GeoJson`): outside the area it shows a warning at once, turns the marker red, reports `onCoverage(false)`, and the guided forms and the chat's "Send this location" refuse the point. Without an area (an API that has none yet, an unsupported country, an error) there is no overlay and no check, never a block. The Ask AI chat has forms that send fixed messages the system prompt tells the model to read: map, calendar, `FertilizerPicker`, and `ChatPickers.tsx` (`FieldPicker`: size, unit, yield class, cassava price, budget, risk attitude; `PracticesPicker`: operations, methods, costs; `IntercropPicker`: second crop and price), with "Details" chips above the input that show which were sent (read back from the user messages, so they also work for saved conversations) and reopen the form. `ChatView` asks for the country first (from the API's list), builds the grouped example questions from it, queues messages sent while an answer is running, offers "Resend last message" under a finished answer (and "Try again" on an error), which asks again for the answer to the last user message without repeating the message and replaces the earlier answer and its tool steps, and shows server `warning` events (an MCP server that could not be reached). `src/mcp/servers.ts` lists the servers; `src/mcp/useMcpServers.ts` connects with the SDK's `StreamableHTTPClientTransport` through the same-origin `/gateway` path (Vite `server.proxy` in dev, `nginx.conf` in Docker), so servers without CORS support such as Akilimo 2.0 work. `ToolRunner` lists connected servers' tools and renders `SchemaForm`, a generic JSON-Schema form (nullable unions, enums, nested objects, arrays, JSON fallback) so the user enters every input; `ServerPanel` holds the connect switches and the in-memory Akilimo 2.0 key; `ActivityFeed` logs real calls. Any object in a schema with numeric lat/long-named fields gets a Leaflet/OpenStreetMap `MapPicker` (react-leaflet 4, since 5 needs React 19), centred on the object's `country_code` and rounding picks to 4 decimals. A pick also reverse-geocodes the point with OpenStreetMap Nominatim (`zoom=3`, one request per click; respect its usage policy) and writes the ISO code into that object's `country_code`/`countryCode`; the async update goes through a ref to the latest value so it does not undo the lat/long change. `src/mcp/presets.ts` holds per-tool prefill buttons keyed `${serverId}::${toolName}`; the compute presets fill typical defaults without overwriting user input, and load a country's available fertilizers plus middle-band fertilizer (`price_per_bag`) and cassava (`average_price`) prices via `get_reference_data`, skipping 0 and negative placeholder bands.

## Build / deployment gotchas

- The server is built with Vite in library/SSR mode (`packages/server/vite.config.ts`) to `dist/index.cjs`; runtime deps (`@modelcontextprotocol/sdk` and `zod` including their subpaths, `axios`, `express`, `cors`) are externalized, everything else (including `@akilimo/shared`) is bundled. A new runtime dependency must be added both to the server's `package.json` and to the Vite `external` list.
- Two images, both built with the repo root as context: `Dockerfile` (MCP server) and `packages/web/Dockerfile` (static web UI served by unprivileged nginx on 8080; `packages/web/nginx.conf` also proxies `/gateway/` and `/api/` to `akilimo-mcp:3000` and `/proxy/ollama/` to `OLLAMA_UPSTREAM`, resolving via Docker DNS at request time). Compose adds a `db` service (postgres:17-alpine, internal network only, `akilimo-db` volume) created from the same required `DB_*` values the server gets; `akilimo-mcp` waits for it to be healthy; the server image ships the `drizzle/` SQL migrations and applies them itself at start (no database CLI and no `openssl` in the image). `drizzle-orm` and `pg` are in the server's Vite `external` list (and so runtime dependencies); `drizzle-kit` is a dev dependency. `pnpm-workspace.yaml` `allowBuilds` only needs `esbuild`. A `weather-mcp` compose service (`docker/weather-mcp/Dockerfile`) runs the third-party weather MCP server on the internal network. Each installs only its own package via `pnpm install --filter <pkg>...`, but every workspace `package.json` must still be copied for the `--frozen-lockfile` check.
- Images are published to GHCR only (`.github/workflows/docker-publish.yml`: `ghcr.io/iita-akilimo/akilimo-mcp-agent`, `-web` and `ghcr.io/iita-akilimo/akilimo-weather-mcp` (from `docker/weather-mcp/Dockerfile`), `latest`/semver/`sha-` tags, PRs build without pushing). Base images are build args (`NODE_IMAGE`, `NGINX_IMAGE`; repo variables of the same names in CI) so they can come from a mirror instead of Docker Hub. Production: service `mcp` in the `akilimo-mcp` stack of the `proxy-tool` repo (next to `web` at `127.0.0.1:9102`/`agent.akilimo.org`, `weather-mcp` and `agriculture-mcp`, both internal only; the API stays in the `akilimo` stack and is reached over the shared `internal` network), `127.0.0.1:9101`, Caddy site `akilimo-mcp.akilimo.org` exposing only `/mcp`, `/sse`, `/messages`, `/health`; the API is reached internally at `http://akilimo-api/api`.
- The server image's runner gets its `node_modules` from `pnpm deploy --prod --legacy`, so runtime versions come from `pnpm-lock.yaml`. The pnpm version is pinned by `packageManager` in the root `package.json`. The server exposes `GET /health` (HTTP mode only) for the Docker `HEALTHCHECK`.
- pnpm 12 has written a peer-less `@modelcontextprotocol/sdk` version (`1.32.2` instead of `1.32.2(zod@3.25.76)`) into the web importer, leaving a dangling `node_modules` link and "Cannot find module '@modelcontextprotocol/sdk/…'" in `tsc`. Fix the importer entry in `pnpm-lock.yaml` and run `pnpm install --frozen-lockfile`.
- Open WebUI reaches Ollama on the Docker host via `host.docker.internal` (override with `OLLAMA_BASE_URL`); host Ollama must listen beyond `127.0.0.1` (`OLLAMA_HOST=0.0.0.0`). The compose file expects an external `dokploy-network` Docker network.
- `docs/ANDROID_INTEGRATION.md` explains how the AKILIMO Android app can call this server (protocol details verified against a running server: `Accept` header required, stateless, SSE-framed answers; tool arguments and real responses; OkHttp/Kotlin samples that were not compiled).
- `docs/MCP_CONNECTION_GUIDE.md` documents client configs and the hosted endpoints (Akilimo 1.0, this server, at `akilimo-mcp.akilimo.org/mcp` and `/sse`; Akilimo 2.0 at `mcp.akilimo.org/mcp`).
- `docs/PRD_MCP_HUB.md` is the (not yet built) product requirements for the AKILIMO MCP Hub: one `/hub/mcp` endpoint serving every registry server's tools behind one admin-issued key per integrator.
